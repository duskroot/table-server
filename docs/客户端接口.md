# 开局游戏客户端接口

给小程序 / Cocos 客户端使用。服务端权威发牌、摇点和身份，客户端只渲染快照和事件，不要自己算胜负。

下面所有路径都接在这个根地址后面。

## 调用约定

所有接口都是 POST，路径：

```text
POST /table/v1/{service}/{Action}
```

`service` 小写，`Action` 为 PascalCase。请求体是 JSON，字段名大小写敏感。

除登录和健康检查外，每个请求带登录令牌，二选一：

```http
Authorization: Bearer <Token>
X-Token: <Token>
```

业务成功和业务失败的 HTTP 状态码都是 `200`。先看有没有 `Error`。

成功：

```json
{
  "ResponseMetadata": {
    "RequestId": "123e4567-e89b-12d3-a456-426614174001",
    "Action": "DescribeSnapshot",
    "Version": "v1",
    "Service": "Play"
  },
  "Result": {}
}
```

失败：

```json
{
  "ResponseMetadata": {
    "RequestId": "123e4567-e89b-12d3-a456-426614174001",
    "Action": "SubmitAction",
    "Version": "v1",
    "Service": "Play"
  },
  "Error": {
    "Code": "400202",
    "Message": "还没轮到你",
    "Detail": ""
  }
}
```

`RequestId` 发给服务端排查。`Detail` 可能没有。离开房间、踢人、解散房间成功时 `Result` 是空字符串 `""`。

## 客户端主循环

1. `wx.login` 拿到 `code`，调用 `LoginByWechat`，保存 `Token`。
2. 房主 `CreateRoom`，其他人用 6 位 `Code` 调用 `JoinRoom`。
3. 每个人 `SetReady`。房主 `StartPlay`，保存返回的 `PlayId`、`Seat`、`Cursor`。
4. 对局中每秒调用一次 `PullEvent`，把返回的 `Cursor` 存下来，下次原样传回去。
5. 按钮只根据 `DescribeSnapshot` 或 `ListLegalAction` 的 `Legal` 渲染。轮到谁看 `Legal`，不要只看公开区里的 `Turn`。狼人杀夜里公开区的 `Turn` 固定是 `0`。
6. 出手调用 `SubmitAction`。`ClientSeq` 从 1 开始，每次新动作加 1。超时、断网重试必须用同一个 `ClientSeq`。返回 `Idempotent: true` 表示这次是重放，不要再播一遍动画。
7. `Settled` 为 `true` 后停止出手。结算看事件 `Settle`。房间回到 `open`，准备状态被清空，下一局要重新准备。
8. 断线重进：`DescribeSnapshot` 拿全量，再用上次的 `Cursor` 调 `PullEvent` 补事件。

回合倒计时 20 秒，以快照里的 `Deadline`（UTC，RFC3339）为准。到点由服务端代操作，客户端不用补发超时动作。

## 扑克牌

```json
{ "Rank": 1, "Suit": 0 }
```

`Rank`：1 是 A，11 J，12 Q，13 K。`Suit`：0 黑桃，1 红心，2 梅花，3 方块。

大小牌比较时 A 最大，其次 K 到 2；点数相同则花色数字大的赢。十点半的 `Sum` 是半点的 2 倍：A 为 2，2 到 10 为 `点数 × 2`，J/Q/K 为 1。界面上的点数用 `Sum / 2`，大于 `10.5`（`Sum > 21`）为爆牌。

## 登录

### LoginByWechat

`POST /table/v1/session/LoginByWechat`，不需要 Token。

```json
{ "Code": "wx.login 的 code", "Nickname": "可选，最多 32 字", "Avatar": "可选" }
```

```json
{ "Token": "...", "UserId": 1, "Nickname": "", "OpenId": "..." }
```

联调环境没有配置微信 AppId 时，`OpenId` 为 `dev_` 加 `Code`。同一个 `Code` 会回到同一个用户。

### DescribeSession

`POST /table/v1/session/DescribeSession`，请求体 `{}`。

```json
{ "UserId": 1, "Nickname": "", "Avatar": "", "OpenId": "..." }
```

### DescribeHealth

`POST /table/v1/session/DescribeHealth`，不需要 Token。`Result` 为 `{ "Status": "ok" }`。

## 房间

房间状态：`open` 可准备和开局，`playing` 对局中，`closed` 已解散。

`RoomView`：

```json
{
  "RoomId": "r_...",
  "Code": "123456",
  "HostUserId": 1,
  "GameCode": "zhajinhua",
  "Variant": "classic",
  "Status": "open",
  "Config": {},
  "MaxSeats": 6,
  "PlayId": "",
  "Members": [
    { "Seat": 1, "UserId": 1, "Nickname": "甲", "Ready": false, "Away": false }
  ]
}
```

`PlayId` 为空表示当前没有进行中的对局。座位从 1 开始。

### CreateRoom

```json
{
  "GameCode": "zhajinhua",
  "Variant": "classic",
  "Config": { "Ante": 1, "Chips": 100 },
  "MaxSeats": 6
}
```

`Variant` 省略时为 `classic`。`MaxSeats` 为 0 时用该玩法的最大人数。`Config` 必须是 JSON 对象。创建者坐在 1 号位，此时还未准备。

### UpdateRoom

对局未开始时，房主可改玩法、变体、配置和座位数。座位数不能小于当前人数。请求在 `CreateRoom` 的字段上增加 `RoomId`。

### JoinRoom

```json
{ "Code": "123456" }
```

已在房间里再次调用会回到原座位；若之前离座，会取消离座。对局中不能新加入。

### ListRoom

请求体 `{}`。`Result` 是当前用户未关闭房间的 `RoomView` 数组。

### DescribeRoom

```json
{ "RoomId": "r_..." }
```

### SetReady

```json
{ "RoomId": "r_...", "Ready": true }
```

只有 `open` 可以准备。返回更新后的 `RoomView`。

### StartPlay

见下一节。只有房主能开局。所有未离座的人都要已准备，且人数达到玩法下限。离座的人不进入这一局。

### LeaveRoom

```json
{ "RoomId": "r_..." }
```

未开局时离开并让出座位。房主离开时，座位号最小的人成为房主；房间没人则关闭。对局中离开只标记 `Away: true`，座位保留，可再 `JoinRoom` 回来。

### KickMember

房主在未开局时踢人。不能踢自己。

```json
{ "RoomId": "r_...", "UserId": 2 }
```

### TransferHost

未开局时房主移交。

```json
{ "RoomId": "r_...", "UserId": 2 }
```

### DeleteRoom

房主解散。进行中的对局会被中止，不写战绩。

```json
{ "RoomId": "r_..." }
```

## 对局

### StartPlay

`POST /table/v1/play/StartPlay`

```json
{ "RoomId": "r_..." }
```

返回 `Snapshot`，字段见下。

### DescribeSnapshot

```json
{ "RoomId": "r_...", "PlayId": "p_..." }
```

`RoomId` 可省略。`Snapshot`：

```json
{
  "PlayId": "p_...",
  "RoomId": "r_...",
  "GameCode": "zhajinhua",
  "Variant": "classic",
  "Seat": 1,
  "Cursor": 3,
  "Phase": "play",
  "Settled": false,
  "Deadline": "2026-11-12T08:00:20Z",
  "Public": {},
  "Private": {},
  "Legal": [{ "Type": "Bet", "Hint": "下注" }]
}
```

`Public` 所有人相同。`Private` 只有当前 `Seat` 能看到。`Legal` 是当前可以点的动作，空数组表示现在不能出手。

### ListLegalAction

请求体与 `DescribeSnapshot` 相同。

```json
{ "PlayId": "p_...", "Seat": 1, "Legal": [] }
```

### PullEvent

```json
{ "PlayId": "p_...", "Cursor": 0, "Limit": 100 }
```

`Cursor` 是客户端已经处理过的最大 `Seq`，第一次传 `0`。`Limit` 默认 100，最大 200。

```json
{
  "PlayId": "p_...",
  "Cursor": 4,
  "Events": [
    { "Seq": 3, "Type": "Bet", "Payload": {} },
    { "Seq": 4, "Type": "Settle", "Payload": {} }
  ]
}
```

没有新事件时 `Events` 为 `[]`，`Cursor` 保持请求值。私密事件不会出现在别人的列表里。

### SubmitAction

```json
{
  "RoomId": "r_...",
  "PlayId": "p_...",
  "Seat": 1,
  "ClientSeq": 1,
  "Action": { "Type": "Bet", "Payload": { "Amount": 2 } }
}
```

`Seat` 可以不传。传了就必须等于自己的座位。无参数的动作，`Payload` 省略或传 `{}`。

```json
{ "PlayId": "p_...", "Cursor": 4, "Idempotent": false }
```

出手后的画面以随后的 `PullEvent` 或再拉一次 `DescribeSnapshot` 为准。`SubmitAction` 本身不返回新快照。

## 战绩

分数只作局内计分，不对应现金。

### ListRecord

```json
{ "GameCode": "", "Page": 1, "PageSize": 20 }
```

`GameCode` 为空表示全部。`Page` 从 1 开始，`PageSize` 最大 50，默认 20。

```json
{
  "Page": 1,
  "PageSize": 20,
  "Items": [
    {
      "PlayId": "p_...",
      "RoomId": "r_...",
      "GameCode": "dice",
      "Variant": "classic",
      "Seat": 1,
      "Delta": 1,
      "Detail": {},
      "CreatedAt": "2026-11-12T08:00:00Z"
    }
  ]
}
```

这里只返回当前用户自己的那一行。

### DescribeRecord

```json
{ "PlayId": "p_..." }
```

返回该局所有座位的 `Items`，以及 `PlayId`、`RoomId`、`GameCode`、`Variant`。只有参与过这局的人能看。

## 玩法

`CreateRoom.GameCode` 使用下表的代号。人数含两端。

| GameCode | 玩法 | 人数 | Variant | Config |
|---|---|---|---|---|
| `dice` | 摇骰子 | 2–8 | `classic` | `{ "Count": 2 }`，1 到 5，默认 2 |
| `highcard` | 大小牌 | 2–8 | `classic` | `{}` |
| `tenhalf` | 十点半 | 2–6 | `classic` | `{}` |
| `zhajinhua` | 炸金花 | 2–6 | `classic` | `{ "Ante": 1, "Chips": 100 }` |
| `douniu` | 斗牛 | 2–6 | `classic` | `{}` |
| `spy` | 谁是卧底 | 4–10 | `classic` | 见下文 |
| `wolf` | 狼人杀 | 6–12 | `classic` 或 `witch` | `{}` |

### 摇骰子 `dice`

阶段 `roll`，然后 `end`。按座位顺序，当前座位 `Roll`，无参数。每人摇 `Count` 颗 1 到 6 的骰子。点数和最高的人获胜，并列则平分。

`Public`：`Turn`、`Count`、`Rolls`。`Rolls` 的元素是 `{ "Seat", "Dice": [1, 6], "Sum" }`。`Private` 为 `{}`。

事件 `Rolled`：`{ "Seat", "Dice", "Sum" }`。超时自动摇。

### 大小牌 `highcard`

阶段 `draw`，然后 `end`。当前座位 `Draw`，无参数，抽一张明牌。A 最大。

`Public`：`Turn`、`Drawn`。`Drawn` 的元素是 `{ "Seat", "Card" }`。`Private` 为 `{}`。事件 `Drawn` 的载荷与抽到的那一项相同。超时自动抽牌。

### 十点半 `tenhalf`

座位号最小的人是庄家。阶段 `play` 是闲家要牌，`dealer` 是庄家自动要牌，然后 `end`。

闲家动作：`Hit`、`Stand`，都无参数。`dealer` 阶段没有按钮。庄家在半点合计小于等于 7 时继续要牌。闲家各自和庄家比：爆牌输，点数高赢，相同走水（`Delta` 为 0）。

`Public`：`Dealer`、`Turn`、`Hands`。每手是 `{ "Seat", "Cards", "Sum", "Bust", "Done" }`。`Private` 为 `{}`。事件 `Dealt` 带 `Dealer` 和 `Hands`。超时闲家视为停牌。

### 炸金花 `zhajinhua`

阶段 `play`，然后 `end`。开局每人扣底注，发 3 张暗牌。

| 动作 | 何时可点 | Payload |
|---|---|---|
| `Look` | 还没看牌、没弃牌，不要求轮到自己 | 无 |
| `Bet` | 轮到自己 | `{ "Amount": 2 }`，必须大于等于当前 `Stake` |
| `Compare` | 轮到自己 | `{ "TargetSeat": 3 }` |
| `Fold` | 轮到自己 | 无 |

看过牌再下注或比牌，实际扣款是 `Amount` 或当前注的 2 倍。筹码不够会被拒绝。只剩一人时结束。`Delta` 是最终筹码减去开局筹码。

`Public`：`Pot`、`Stake`、`Turn`、`Folded`（座位数组）、`Looked`、`Chips`（`{ "Seat", "Chips" }`）。`Private`：看牌之后才有 `Cards`，否则没有这个字段。事件有 `Deal`、`Bet`（`Seat`、`Amount`、`Paid`）、`Settle`。超时视为弃牌。

### 斗牛 `douniu`

阶段 `grab`，全部人抢完后直接 `end`。每人 5 张暗牌。抢庄不分先后，没抢过的人都可以 `Grab`：

```json
{ "Multiple": 0 }
```

`Multiple` 为 0 到 3。倍数最高者为庄，相同则座位号更小者为庄。都选 0 时，最小座位当庄，结算倍数按 1。牛牛大于 9 大于没牛；点数相同庄家赢。每个闲家和庄家结算，输赢绝对值等于庄家倍数。

`Public`：`Grabs` 为已抢列表 `{ "Seat", "Multiple" }`。结束后还有 `Banker`、`Multiple`。`Private`：自己的 `Cards`。全部明牌在 `Settle` 事件的 `Hands` 里：`{ "Seat", "Cards", "Niu" }`，`Niu` 为 0 表示没牛，10 表示牛牛。超时未抢按 0 倍。

### 谁是卧底 `spy`

阶段 `describe` 发言，然后 `vote` 投票，然后 `end`。

`Config`：

```json
{
  "CivilianWord": "牛奶",
  "SpyWord": "豆浆",
  "SpyCount": 1,
  "BlankCount": 0
}
```

两个词都省略时，从内置词对里随机抽一对。只填一个会开局失败。卧底加白板必须少于总人数，并且至少留下 2 名平民。默认 1 名卧底、0 名白板。

`Speak`：`{ "Text": "一种喝的" }`，去掉空白后 1 到 40 个字。`Vote`：`{ "TargetSeat": 2 }`，不能投自己。按座位轮流。平票卧底胜；投出的是卧底则平民和白板胜；投出平民或白板则卧底胜。

`Public`：`Turn`、`Speeches`（`{ "Seat", "Text" }`）、`Votes`（`{ "Seat", "TargetSeat" }`）。`Private`：`Role` 为 `civilian`、`spy` 或 `blank`，以及自己的 `Word`。白板的词是空字符串。发言超时自动说「……」。

### 狼人杀 `wolf`

`Variant` 为 `classic`：2 狼、1 预言家，其余村民。`witch` 再把 1 名村民换成女巫。

阶段顺序：`night_wolf`、`night_seer`、`night_witch`、`day_speak`、`day_vote`。预言家已死则跳过查验。只有 `witch` 变体且女巫存活才有用药阶段。未分胜负则回到夜里。

| 阶段 | 动作 | Payload |
|---|---|---|
| `night_wolf` | `Knife` | `{ "TargetSeat": 3 }`，目标必须存活 |
| `night_seer` | `Check` | `{ "TargetSeat": 3 }` |
| `night_witch` | `Potion` | `{ "Save": false, "Poison": -1 }` |
| `day_speak` | `Speak` | `{ "Text": "我觉得 3 号" }`，1 到 40 字 |
| `day_vote` | `Vote` | `{ "TargetSeat": 3 }`，不能投自己，目标必须存活 |

同一夜不能既救又毒。`Poison` 为 `-1` 表示不用毒药，请显式传递。解药和毒药各一次。

夜里 `Public.Turn` 是 `0`，能不能操作只看 `Legal`。`Public` 还有 `Seats`、`Alive`、`Dead`、`Speeches`、`Votes`。

`Private` 按身份不同：

- 狼人：`Role` 为 `wolf`，`Wolves` 是其他狼人的座位。
- 预言家：`Role` 为 `seer`，`Checks` 为 `{ "TargetSeat", "Wolf" }`。
- 女巫：`Role` 为 `witch`，`Potions` 为 `{ "SaveLeft", "PoisonLeft", "Knifed" }`。
- 村民：`Role` 为 `villager`。

活狼为 0 则好人胜。活狼人数大于等于其余存活人数则狼人胜。公开事件有 `Start`、`Dawn`（`Dead` 座位数组）、`VoteResult`（`Out`，平票时没有人出局）、`Settle`。

## 错误码

| Code | 含义 |
|---|---|
| 100001 | 系统错误 |
| 100002 | 请求体不是合法 JSON |
| 100003 | 接口不存在 |
| 200001 | 未登录或 Token 失效 |
| 200002 | 微信登录失败 |
| 300001 | 房间不存在 |
| 300002 | 房间已关闭 |
| 300003 | 座位已满 |
| 300004 | 仅房主可操作 |
| 300005 | 不在房间中 |
| 300006 | 对局进行中，当前不能做这件事 |
| 300007 | 当前没有进行中的对局 |
| 300008 | 仍有玩家未准备 |
| 300010 | 人数不足 |
| 300011 | 你已离座 |
| 300012 | 没有这条战绩 |
| 300013 | 房间参数不正确 |
| 400201 | 当前不能这样出牌 |
| 400202 | 还没轮到你 |
| 400203 | 座位不匹配 |
| 400204 | 动作参数不正确 |
| 500001 | 玩法不存在 |
| 500002 | 牌堆不足 |
| 500003 | 结算缺失 |

Token 失效时重新 `wx.login` 并调用 `LoginByWechat`。`400202` 通常是快照旧了，重新 `DescribeSnapshot`。
